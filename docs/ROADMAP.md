### 2. 집안 물건 관리 세션
- 실물 저장소(수납 위치) + 물건 인벤토리 관리 = 독립 채널/기능.
- **씨앗**: `workspace/files/484003220344012801/수납.md` → 독립 채널로 승격.
- **핵심 설계 질문(미해결)**: 실물 저장소와 물건을 어떻게 묘사/모델링할지.
  - 위치 계층(방 > 가구 > 칸)? 물건↔위치 관계? 사진 연동? "드라이버 어디 뒀지" 검색?
  - DB 테이블 vs 마크다운 노트 vs 혼합?

### 3. 건강기록 세션
- 건강 기록 전용 세션(채널).
- 열린 질문: 무엇 기록(검진/투약/증상/수치/예약)? 개인별 분리? 기존 파일(간염검사결과 등) 연동?
- 투약 리마인드 = 반복 알람(Step 9) 재활용. 프로액티브 확인은 #4 필요.

### 4. 알람 → 스케줄러 (내부 펑션 활성화)
- **본질**: 지금 알람은 발화 시 **정적 텍스트만 발송**(`⏰ content`, dead-end). 이걸 **스케줄러**로 승격 — 발화가 내부 펑션을 활성화.
- **기제 = 기존 `{{}}`/`[]` 템플릿 프로토콜 재활용.** 발화 시 content를 raw send 대신 **파이프라인에 태운다**:
  - **template 모드**: content를 게이트웨이 템플릿 처리기(`processTemplates`/`extractAlarms`/`processGuroTemplates`)에 통과 → 예약된 `{{...}}` 자동 실행(결정적 액션).
  - **agent 모드**: content를 에이전트에 프롬프트로 투입(합성 인바운드 = `handleText`형) → 에이전트 응답이 정상 파이프라인 거쳐 발송(동적 요약/판단).
- "아침 브리핑"(카드값 준비 확인 등)은 agent 모드의 **응용례 하나**일 뿐. 핵심은 스케줄러화.
- **미해결/설계 concern**:
  - **무인 실행 안전**: 스케줄 발화는 사용자 부재 중 실행 → 자동 액션(예: 자동 주차등록)·에이전트 무인 구동. 폭주/루프/권한 가드 필요. 어떤 템플릿을 무인 자동실행 허용할지.
  - 알람 스키마에 mode(template/agent) 필드? content가 곧 템플릿/프롬프트.
  - TODO/prep-status 저장소는 브리핑 응용 시에만 필요(핵심 아님).
